# 故障降级验证

## 已自动化覆盖

- ASR 消费队列饱和时丢弃转写帧，不阻塞录音分支；
- 暂停、恢复、结束的 generation 隔离，晚到结果不会写入新会议；
- Provider 任务失败后的重试、重启恢复和重复任务合并；
- 最终转写先持久化再通知界面；
- 录音文件使用临时文件和 checkpoint，异常关闭后保留已完成页；
- 旧版 localStorage 文本会议的幂等迁移。

## 发布前人工注入

1. 开始双源录音后断开网络 30 秒，再恢复网络。
2. 录音中删除或填错 ASR Key，确认录音不停止。
3. 录音中拔出麦克风，确认系统声音继续；重新插入后的行为需记录。
4. 暂停后强制结束应用进程，再启动应用检查会议和录音文件。
5. 点击结束后立刻创建下一场会议，确认旧任务只更新旧会议。
6. 将应用数据目录所在磁盘逼近满盘，确认错误可见且不宣称保存成功。

每次故障注入都要核对 SQLite 会议状态、录音文件是否可解码，以及界面是否把“录音”和“转写”分别呈现。当前未自动化的设备热插拔与磁盘满场景必须明确记为人工项。
